About Our Technology

When the OS experiences a page fault, it uses the I/O wait time to ask an AI predictor (GRU/LSTM) to produce a short, ordered multi-step prediction chain. The OS keeps running LRU as the fast critical path; the AI acts as an advisor whose suggestions are accepted only when a dynamic trust score (fusing per-page fuzzy μ, short term S, and long-term reality W) is high. Predictions are validated step-by-step and the system updates page-level and global trust using rewards/penalties.

How It Works

01

Model Activation Policy

Model runs only on page fault: when OS experiences a page fault and starts disk/SSD I/O, model uses that I/O wait time to generate a full prediction chain (one-shot multi-step). This avoids running the model on the critical path.

Chain length is adaptive:
chain_len = min(max_chain, floor(IO_time / model_time_per_prediction))

02

Model Outputs

Ordered predicted pages: p = [p1, p2, p3, ...] (head is immediate next).

Per-step confidences conf = [c1, c2, ...] (sigmoid outputs — fuzzy confidences).

Optionally: model also outputs cp (immediate next) and long chain, and can produce per-prediction μ proposals. Model inputs: history, mu values for pages in history, and W (global reality weight) and S optionally.

03

Continuous Chain Usage

For every incoming page access (normal CPU access), follow:

1. If q (active chain) exists → compare actual page c with q[0] (head). o If c == q[0] → Match: reward model, advance q (pop head). Update mu[c] and S. No LRU involvement. o If c != q[0] but page is in memory (no page fault) → Mismatch without fault: do NOT discard the chain.

2. If a true page fault occurs (page not in memory) → follow Page Fault Handling.
